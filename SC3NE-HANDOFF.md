## What it is

A single self-contained HTML file. A 3D world made entirely of flat
cards — images, drawings, animation — positioned in metres and judged
through a camera. Not a 3D engine and not trying to be. The vocabulary is
IMAGE → PLANE → SPACE → TIME → CAMERA.

Runs on iPad (in PAJA, a local runner) and desktop browsers. WebGL2, no
depth buffer, painter's order.

## How to build it

The source is a module tree; the HTML is generated by concatenation.

```
cd /home/claude && unzip -q sc3ne-modules.zip
cat > build.py <<'EOF'
import json,sys,os
out=sys.argv[1] if len(sys.argv)>1 else 'sc3ne.html'
man=json.load(open('sc3ne/manifest.json'))
txt="".join(open(os.path.join('sc3ne',p)).read() for p in man)
open(out,'w').write(txt)
print("built",txt.count("\n"),"lines")
EOF
python3 build.py sc3ne-build106.html
```

**Always check the JavaScript parses before shipping:**

```
python3 -c "
t=open('sc3ne-build106.html').read()
js=t.split('<script>\n',1)[1].rsplit('</script>',1)[0]
open('/tmp/c.js','w').write(js)"
node --check /tmp/c.js
```

**And grep the built file for every new symbol.** A patch script that fails
halfway leaves earlier edits applied and later ones missing, and the result
still builds. This has caused more lost time than anything else.

Layout: `shell/` html · `brick/` css and self-contained subsystems ·
`seam/` the core (state, world, render, input, panels) · `tool/` copy,
recipes, bridge, landscape.

**Test it headless before shipping.** React comes from a CDN the work
container usually cannot reach; esbuild and React 19 sit in
`/opt/npm-tools/node_modules`, so bundle a stand-in
(`import * as React from 'react'; import * as RD from 'react-dom';
import * as C from 'react-dom/client'; window.React=React;
window.ReactDOM=Object.assign({},RD,C);`), route both CDN URLs to it in
Playwright, and inject `window.__ev=s=>eval(s);` just before `boot();` —
a direct eval inside the closure reaches every function and `S`. Build 103
was checked that way: every room's buttons pressed, plus targeted tests.

## State at build 106

**Working:** planes in four facings · draw surfaces and freehand lines ·
PNG-sequence import with per-copy playback · scatter brush · paths ·
recipes (grid, cut stack, field) that stay editable · landscape from
plates plus connecting planes · groups · marquee and multi-select ·
snapping by centre/edge/corner/group with a chosen pivot · particles ·
bake to plates and paint with blend modes · colour grade and LUTs ·
slides with per-slide timing, text, visibility and scroll transport ·
reflections · HDRI sky and light-from-sky · MIDI/MPE bridge in settings ·
export (PNG, depth, masks, plates, scene file, web embed).

**New in 103:** YKB — a control channel per layer, painted on the card in
the view. Mappings MATTE and DEPTH; views CONTROL / RENDER / VISIBLE.
Lives in `brick/ykb.js`; the shader reads it as `uCtl`.

**New in 104:** WEB room (`tool/web.js`) — the scene as a page: scroll that
steps, snaps or flies the camera through the views in order, move times by
distance (far moves faster), a page panel per view, an address per view.
GAME room (`tool/game.js`) — layers that speak when clicked in presentation,
zones that answer when a view is reached inside them, a twelve-step journey,
voices drawn from public-domain texts and from lines written for SC3NE.
Presentation no longer shows editor chrome.

**New in 105:** four-corner surfaces (`seam/quad.js`, face `'quad'`) — any
angles, drawn from corner uniforms, picked by triangles, sorted with the
ground when `ground` is set, culled from behind when `cull` is set, lit by
the sun's angle. LANDSCAPE has a broken-grid mode (uneven, off-square,
subdivided, terraced, with risers). BUILD room (`tool/build.js`): house,
round, bridge, stairs, tube — recipes of quads that follow the gizmo; grow
a surface from any edge; drag corners that catch on corners. Imported
pictures are sorted into kinds by name or folder (English and Finnish).
Menus: room headers, Swiss section headings, full-width sliders, folding
explanations, sectioned SCENE / CAMERA / LIGHT / settings.

**New in 106:** the node graph does things to the scene, not only grades.
`brick/nodes.js` holds types, evaluation and the editor; `tool/graph.js`
holds adding, templates, components and the panel.
- Two socket kinds: square carries a set of layers (*things*), round carries
  a value (*signal*, −1…1). A signal wire goes onto a parameter (`port:
  'p:<key>'`) with its own depth; the parameter swings around its own value.
- MAKERS (image, array, landscape, building, light-as-glow) own layers
  tagged `l.node`. Each keeps a signature of what shapes it (`_built`) and
  rebuilds only when that changes; moved with the gizmo, it rebuilds where
  it now stands (`anchor` / `origin`). A layer whose node is gone is removed
  on the next evaluation.
- SHAPERS (transform, look, animate) never touch a layer. They write a work
  copy in `FXW` (pos, yaw, height, wscale, opacity, hidden, assetId, anim,
  ntint, solid); `pass()` draws `fxOf(l)`. Picking and the gizmo stay on the
  real layer — a moved copy is selected where it really stands.
- WORLD: light drives `S.sun` / `S.ambient` while it exists; particles own
  an emitter `nd:<node id>`.
- COMPONENT: nodes folded into `n.sub`, flattened at evaluation with ids
  `<component>/<inner>`; promoted controls in `n.expose`, their values in
  `n.p['<inner>.<key>']`.
- The graph evaluates inside `draw()` (`graphEnsure`), every frame while
  something moves (`graphLive`), with `GT` as its clock. `S.nodeRun` holds it.
- The old grading chain (band → grade/fog/tint/fade → out) is unchanged and
  cannot be wired to scene nodes.

**Not built:** instanced drawing · picking the moved copy · signals out of a
component · more YKB mappings (GLITCH, TIME, LIGHT).

**Scene files are at version 6.** `migrateDoc` in `seam/store.js` runs on
load. Any new field on a layer or shot needs a line there, or old scenes
break.

## Rules that matter

1. **Additive.** Old scenes must keep opening. Existing tools keep working.
2. **Camera-first.** If the camera sees it correctly, it works. Imperfect
   geometry is acceptable; composition solves geometry.
3. **Cheap tricks are the point.** A mirrored copy, a crossed card, a
   stack of transparent plates. Not simulation.
4. **One tool at a time**, tested before the next.
5. Every new capability should make an unusual visual result *easy*. If it
   only adds technical complexity, reconsider it.
